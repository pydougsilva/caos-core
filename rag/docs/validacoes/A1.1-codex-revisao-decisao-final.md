# A1.1 — Revisão do Codex + Decisão Final + Rastreabilidade

---

## PARTE I — REVISÃO DO CODEX (registro institucional)

Esta seção registra institucionalmente a revisão independente entregue pelo agente_executor
em resposta ao pacote de auditoria A1.0.

### Posição central do revisor

A proposta não deve ser chamada de "Indiferença de Agente".
O nome correto é **Bootstrap Institucional Verificável** ou **Camada de Entrada por Adaptadores**.

O problema que a proposta resolve não é "tornar agentes indiferentes" —
é garantir que qualquer agente **prove que carregou o protocolo canônico antes de operar como C.A.O.S**.

Esta reformulação é arquiteturalmente superior à original:
- Remove a ambiguidade do termo "indiferença" (que implica intercambiabilidade, não verificação)
- Foca no RESULTADO (bootstrap verificável) em vez do MECANISMO (configuração paralela)
- É compatível com P14 quando implementado como ponteiro, não como duplicata

---

### Respostas às 5 perguntas abertas

**Q1 — P14 é inviolável?**

Sim, como princípio estrutural.
Um adapter com nome de ferramenta não viola P14 por si só se for apenas ponteiro técnico.

| Situação | P14 | Diagnóstico |
|---|---|---|
| `.claude/instructions.md` com protocolo duplicado | VIOLA | Identidade vira requisito institucional |
| `CLAUDE.md` que diz "carregue AGENTS.md" | COMPATÍVEL | Ponteiro técnico — ferramenta é meio, não fim |
| `.caos/adapters/claude.md` com o mesmo ponteiro | COMPATÍVEL | Namespace do sistema, não do fornecedor |

Regra derivada: viola P14 quando `.claude/`, `.codex/`, ou nome de ferramenta vira **requisito institucional**.
Não viola quando é apenas **mecanismo de compatibilidade técnica** que aponta para AGENTS.md.

---

**Q2 — `orchestrate.sh` é prematuro?**

Sim. Como runtime de orquestração completo, é v7.0+.

Uso aceitável imediato: ferramenta de **auditoria de cold-start** apenas.

```bash
# Uso legítimo agora (diagnóstico, não execução):
caos-check.sh → verifica presença de AGENTS.md, rag/index.md, núcleo mínimo
             → emite recibo: "protocolo carregado" ou "protocolo ausente"
             → NÃO executa handoff, NÃO substitui gate humano, NÃO cria commits
```

Distinção crítica: ferramenta de verificação ≠ orquestrador de execução.
A primeira é segura. A segunda requer v7.0+ e amadurecimento do ecossistema.

---

**Q3 — `CLAUDE.md` vs `AGENTS.md` como source of truth**

`AGENTS.md` permanece a constituição canônica.
`CLAUDE.md` é ponteiro de compatibilidade, se necessário.

```
ERRADO:  renomear AGENTS.md → CLAUDE.md
CORRETO: AGENTS.md (constituição) + CLAUDE.md (adapter-ponteiro que referencia AGENTS.md)
```

Razão: renomear AGENTS.md para CLAUDE.md degradaria o núcleo universal para
dependência de uma ferramenta específica — violação direta de P14.

Hierarquia de autoridade após implementação:
```
AGENTS.md (autoridade máxima — imutável)
CLAUDE.md (ponteiro de compatibilidade — "carregue AGENTS.md")
```

---

**Q4 — State management sem Git conflita?**

Depende do tipo de estado.

| Tipo de estado | Git necessário? | Diagnóstico |
|---|---|---|
| `.caos/runtime.lock` (efêmero, em .gitignore) | NÃO | Compatível — trava operacional local |
| Fila de tarefas, aprovações, ciclos | SIM | Ledger institucional — deve estar no Git |
| Resultados de execução, snapshots, divergências | SIM | Evidência verificável — deve estar no Git |

**Regra derivada:** lock efêmero pode existir fora do Git.
Estado institucional nunca pode sair do Git/snapshot/telemetria.

---

**Q5 — A proposta resolve o problema correto?**

Parcialmente.

O C.A.O.S v5.0 já resolve continuidade via artefatos.
O que ainda faltava: **verificação de que o carregamento realmente ocorreu**.

O novo conceito introduzido pelo revisor: **context_receipt** (recibo de contexto).

```yaml
# context_receipt — estrutura proposta
agente: Claude Sonnet 4.6
timestamp: 2026-05-31T10:00:00
agents_md_carregado: sim
agents_md_versao: "3.0"
index_md_carregado: sim
nucleo_minimo_verificado: sim
modo_operacao: pleno | degradado
ciclo_ativo: ciclo-id
```

O recibo é:
- Criado pelo agente no início de cada sessão
- Armazenado em `.caos/receipts/session-YYYYMMDD.yaml` (efêmero) ou em telemetria (persistente)
- Permite verificar — externamente — que o protocolo foi carregado antes da primeira operação
- É o elo faltante entre "protocolo existe nos artefatos" e "protocolo foi de fato carregado"

### Recomendação de decisão do revisor (posição independente)

```
INCORPORAR PARCIALMENTE

Rejeitar:
- nome "Indiferença de Agente"
- duplicação de AGENTS.md em arquivos de configuração
- scripts de orquestração agora (v7.0+)
- estado institucional fora do Git
- dependência estrutural em nomes de ferramentas

Incorporar:
- renomeação conceitual: "Bootstrap Institucional Verificável"
- adapters como ponteiros (CLAUDE.md → "carregue AGENTS.md")
- context_receipt: recibo de bootstrap verificável
- regra operacional: sem AGENTS.md carregado, agente é genérico (formaliza o axioma existente)
- caos-check.sh: ferramenta de auditoria de cold-start (não orquestrador)
```

### Decisão final

```
DECISÃO: INCORPORAR PARCIALMENTE
Data: 2026-05-31
Autoridade: auditoria dupla convergente (A1.0 + A1.1)
Status: PENDENTE DE SPRINT DE IMPLEMENTAÇÃO
```

**Aprovado para incorporação:**

1. Renomear o conceito: "Bootstrap Institucional Verificável" substitui "Indiferença de Agente"

2. Adapter Layer mínima:
   - `CLAUDE.md` na raiz de cada projeto C.A.O.S como ponteiro para AGENTS.md
   - Conteúdo canônico: "Este projeto usa o protocolo C.A.O.S. Carregue AGENTS.md."
   - Namespace: `.caos/adapters/[ferramenta].md` para adapters alternativos
   - NUNCA duplicar o protocolo — apenas referenciar

3. context_receipt:
   - Estrutura YAML criada pelo agente no início de sessão
   - Verifica: AGENTS.md carregado, versão, modo operacional, ciclo ativo
   - Armazenado em telemetria (persistente) ou `.caos/receipts/` (efêmero)

4. Regra operacional formalizada:
   - "Sem AGENTS.md carregado E sem context_receipt: agente opera como genérico"
   - Formaliza o axioma P9 (isolamento de sessão) como verificação operacional

5. caos-check.sh (futuro, não imediato):
   - Ferramenta de auditoria de cold-start apenas
   - Verifica presença do núcleo mínimo, emite recibo
   - NÃO executa handoff, NÃO substitui gate humano

**Rejeitado:**

- Nome "Indiferença de Agente"
- Duplicação de AGENTS.md em qualquer arquivo de configuração
- Scripts de orquestração como próxima camada (v7.0+)
- `.caos/queue.json` e estado institucional fora do Git
- `.codex/config.toml` como mecanismo de carregamento (incerto, não validado)
- Dependência estrutural em nomes de ferramentas (`claude`, `codex` como requisito)
